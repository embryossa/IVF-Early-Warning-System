# CLAUDE.md — правила проекта Early Warning System (EWS)

Перед работой прочитай этот файл, `PLAN.md`, `docs/METHODOLOGY.md` и `docs/CONTRACTS.md`.
Основной пользовательский вход — скиллы `/ews-run` и `/ews-backfit`; отдельных BAT-файлов
проекта не создавать.

Проект — система раннего предупреждения о проблемах культивирования в лаборатории ЭКО.
Ядро: риск-скорректированный SPC по остаткам «факт − прогноз» поверх замороженного
прогнозного конверта Digital Twin / TabPFN-3, второй контур — абсолютные пороги Венского
консенсуса. Обоснование конструкции — `PLAN.md` §1.

## Два стенда: черновой и лабораторный

Этот рабочий каталог — **черновой стенд на домашнем ПК**. Боевой запуск будет на машине
в лаборатории. Отсюда — неподвижное правило переносимости:

- **Ни одного абсолютного пути в файлах, попадающих в git.** Все машинозависимые пути живут
  только в `config/machine.local.yaml` (в `.gitignore`, шаблон — `.example`). Это касается
  путей к `embryo-lab-data`, Digital Twin, TabPFN-3, Teable, выгрузкам MIRI и PDF
  консенсусов. Перенос в лабораторию = правка одного этого файла.
- В коде — только `pathlib.Path`, никаких строковых склеек с разделителями и никаких
  предположений о букве диска.
- `machine.local.yaml` несёт обязательное поле `environment: draft | production`.
  В режиме `draft` каждый записанный артефакт (CSV/HTML/JSON/карточка тревоги) обязан
  нести штамп `environment=draft` и дату. Черновой отчёт, перепутанный с лабораторным, —
  это ровно тот класс ошибки, ради предотвращения которого система и строится.
- В режиме `draft` система **не поднимает уровень `alert`** — только `watch`.
- Секреты (токены Teable, Airtable) — только `config/settings.local.yaml`, в git не
  попадают, в логи, отчёты и чат не выводятся.
- Переносимые параметры (пороги, окна, гейты) — `config/settings.yaml`, он едет в git как
  есть и при переезде не правится. Если параметр приходится менять при переезде — значит,
  он лежит не в том файле.

Чек-лист переноса — `docs/PORTING.md`.

## Неподвижные решения владельца

- **Тревоги существуют только на T+6.** T0 (день пункции) и T+1 (проверка оплодотворения) —
  чистая регистрация: ничего не оценивают, ничего не поднимают, карты не обновляют. Более
  ранняя тревога — преждевременная паника, которая обесценивает систему быстрее, чем
  пропущенный сигнал.
- **Прогнозный конверт замораживается на T0** и никогда не пересчитывается. Конверт,
  переоценённый после того, как факт стал известен, — не прогноз, и сравнение с ним не
  является ранним предупреждением. Хранится с версией модели и run id.
- Три записи на цикл сохраняются при единственной точке оценки: `2pN`/`Deg`/`3pN` обязаны
  иметь собственную дату записи, иначе на закрытии нечем отделить контур ICSI от контура
  культивирования.
- **Среда (MIRI) — ретроспективный, мягкий шаг.** Выгрузка логов делается раз в 7 дней,
  путь к ней есть только на лабораторной машине. Оценка T+6 обязана завершаться без неё.
  Отсутствие логов помечается `miri_status=pending`, а не трактуется как «событий не было».
  Обогащение средой может повысить `watch → alert`, но никогда не создаёт тревогу и никогда
  не снимает её задним числом.
- **Числа берёт код, текст берёт RAG.** Порог для сравнения приходит только из
  `embryo.kpi.KPI_SPECS` или `config/consensus/*.yaml`. RAG отдаёт формулировку
  рекомендации и цитату и не участвует в решении «сработало / не сработало».
- Пороги Венского консенсуса **не дублируются** в этом проекте. Если значение уже есть в
  `embryo.kpi.KPI_SPECS` — оно импортируется, а не переписывается. В
  `config/consensus/*.yaml` кладутся только цитаты, рекомендуемые действия и те пороги
  (Cairo, Alpha cryo), которых в `kpi.py` нет.
- Лоты среды берутся из Airtable по реальным датам начала и конца использования. Смена
  лота — **кандидат-confounder**, не причина и не оценка качества лота. Событие
  `lot_change` возникает только при реальном пересечении более одного периода лота с окном.
  Если два лота одной позиции открыты одновременно — цикл помечается неразрешённым, а не
  приписывается произвольному лоту.
- Падение покрытия P10–P90 сразу на всех стадиях, включая доКультивационные, — **не** сигнал
  контура культивирования. Разбирается фиксированным порядком трёх гипотез (состав
  пациенток / дрейф модели / общелабораторный фактор), см. `PLAN.md` §6. Эскалацию до
  `alert` блокирует, сами `watch` не гасит.
- Когортный показатель — только `Σ numerator / Σ denominator`, никогда не среднее долей.
  Ноль — наблюдение; пропуск — только пустое значение.
- Единица наблюдения для карт по долям — **эмбрион**, не цикл. Для карт по конверту — цикл.
- `ClR > 100%` — наблюдение о тайминге проверки оплодотворения; `MII > OCC` — добавленные
  размороженные ооциты. Ни то, ни другое не является порчей данных; называть это «data
  integrity / counting mismatch» запрещено. Биномиальный CI в таких строках не считается —
  интервал математически не определён.
- Знаменатель `TGBDR` — 2pN, не число бластоцист. Модельная `good/Bl` (CSDI, шаг воронки
  `Bl→Good`) — другая величина; мост `TGBDR = (Bl→Good) × BlR`. Сравнивать `Bl→Good` с
  порогами TGBDR запрещено.
- Дискриминативные метрики моделей (Brier, ROC-AUC, Acc@0.5) в интерпретацию EWS не входят:
  на когортах этого масштаба они статистически неотличимы от шума.
- Система выдаёт наблюдения и поводы для разбора. Не диагнозы, не назначения, не оценку
  конкретного специалиста. Факт и гипотеза разделяются явно в каждом артефакте.

## Калибровка и уровни тревог

- Пороги карт (`h` для CUSUM, `L` для EWMA) — **не литературные, а измеренные**: их
  подбирает `scripts/ews_backfit.py` симуляцией на истории под целевой ARL, записанный в
  `config/settings.yaml`. До первого бэкфита значения помечены `calibrated: false`.
- **Пока `calibrated: false`, система физически не может выдать `alert`** — только `watch`.
  Это защита от самого дорогого сценария: остановленный лот среды по неоткалиброванному
  порогу. Гейт снимается записью бэкфита, не руками.
- Целевые частоты (решение принято, обоснование — `docs/METHODOLOGY.md` §5):
  `alert` — не чаще **одной ложной на 6 месяцев по системе в целом**; `watch` — не чаще
  **двух ложных в месяц по системе**.
- `alert` требует подтверждения из источника с явно заданным весом: независимый источник
  (смена лота, эпизод MIRI) — сильный; другая метрика того же контура — умеренный;
  **та же метрика на другой карте (CUSUM + EWMA) — слабый и сам по себе до `alert` не
  повышает** (эти карты сильно скоррелированы, это не подтверждение).
- Если бэкфит показал частоту выше целевой — правится `h`, и факт правки печатается.
  Молчаливого занижения порогов нет.

## Поток данных

1. Источник цикла — локальный Teable (REST), куда мастер-таблица OPU синхронизируется раз
   в сутки. Колонки резолвятся через `embryo.ingest` + `columns.yaml` клиники; неизвестные
   имена не угадывать.
2. Псевдонимизация — на границе ingest, до любых расчётов: `embryo.privacy.add_cycle_uid`
   (HMAC). Crosswalk — только в `local_private/`.
3. T0: зарегистрировать и заморозить конверт (TabPFN-3 / CSDI / DT), записать case-mix.
4. T+1: записать `2pN`/`3pN`/`1pN`/`0pN`/`Deg` со своей датой. Ничего не считать.
5. T+6: посчитать все три контура, остатки против конверта, OZEMA, confounders (лоты,
   эмбриолог, врач), обновить карты, вынести решение `ok / watch / alert`.
6. Раз в неделю: обогатить закрытые циклы средой из выгрузки MIRI (replay, детерминированно).
7. Атомарно записать артефакты и run manifest; собрать панель.
8. Агентам отдать только `data/agent_packets/`; обратный join — локальным Python после
   интерпретации.

## Приватность

Мастер-таблица содержит ФИО, ДР и паспортные ID пациентки и мужа. Запрещено помещать в
agent prompt/packet: ID, `_key`, `_join`, ФИО, ДР, сведения мужа, точные идентификаторы
записей. Разрешён `cycle_uid` и аналитические признаки по allow-list. Ни один агент не
читает `data/raw`, `data/local_private` и полные выгрузки. Финальные артефакты с
идентификаторами формирует только Python. Правило наследуется из `embryo-lab-data` без
послаблений.

## Внешние инструменты

Все абсолютные пути — только в `config/machine.local.yaml`:

- `embryo_lab_data.project_dir` — источник импортируемых модулей (`kpi`, `incubator`,
  `ozema`, `lots`, `regression_qc`, `ingest`, `contracts`, `privacy`, `_io`).
  Ставится через `pip install -e`, не копируется.
- `digital_twin.project_dir`, `tabpfn_regression.project_dir` — внешние модели для
  регистрации конверта; запускаются раннерами `embryo.dt_runner` /
  `embryo.tabpfn_regression_runner`.
- `teable.url` / `teable.base_id` — локальный Teable (`127.0.0.1:3000`), токен в
  `settings.local.yaml`.
- `miri_logs.dump_dir` — недельная выгрузка логов инкубатора. На черновом стенде её нет:
  гейт `miri.enabled: false`, шаг мягко пропускается.
- `consensus.pdf_dir` — каталог PDF консенсусов (Vienna, Cairo, Maribor, Alpha, Istanbul,
  Delphi) для сборки корпуса RAG.
- `airtable` — база расходников и лотов среды; токен в `settings.local.yaml`.

Ни один из этих путей не должен появиться в `settings.yaml`, коде, docs или в этом файле.

## Роли Claude Code

Промежуточные роли — `model: haiku` (однотипное объяснение по готовому пакету):
`ews-model-auditor`. Синтез и разбор тревоги — `ews-alert-analyst`, `model: claude-opus-5`
(пин, не alias `opus`). Python считает и классифицирует; агенты только объясняют.

Правило, унаследованное из `embryo-lab-data` и подтверждённое там на реальном отчёте:
после синтеза интерпретации запускается состязательная проверка критиком
(`interpretation-critic` из `embryo-lab-data`) — она ищет числа, не совпадающие с пакетом,
утверждения без основания, гипотезы, поданные как вывод, доли на вырожденных знаменателях и
одно измерение, поданное как несколько независимых подтверждений. Последнее особенно важно
здесь: вся конструкция `alert` построена на понятии независимого подтверждения.
