# Early Warning System for Embryo Culture Conditions

Система раннего предупреждения о проблемах культивирования в лаборатории ЭКО:
ежедневно сопоставляет реальный выход воронки (MII → 2PN → бластоцисты) с тем, чего
от лаборатории вправе ожидать, и отделяет **изменение процесса** от **изменения
состава пациенток**.

Адаптация конструкции из Bormann CL, Curchoe CL, Thirumalaraju P, et al. *Deep
learning early warning system for embryo culture conditions and embryologist
performance in the ART laboratory.* J Assist Reprod Genet 2021;38(7):1641–1646 — для
лаборатории **без тайм-лапс-систем**.

> Исследовательский инструмент, не медицинское изделие. Выдаёт наблюдения и поводы
> для разбора — не диагнозы, не назначения и не оценку конкретного специалиста.

---

## Идея

У Bormann ценна не нейросеть, а конструкция: не ждать частоты беременности (6–8
недель), а следить за предиктором, доступным на 3-й день. Их AI-KPI на изображениях
дал R² = 0.91 с ongoing pregnancy rate и единственный поймал падение исхода на плохом
лоте среды.

Тайм-лапса у нас нет, поэтому вместо предсказанной морфологии используются **три
независимые опоры**, и главное здесь — что ни одна из них не заменяет остальные:

| контур | опора | отвечает на вопрос | двигается вместе с лабораторией |
|---|---|---|---|
| **относительный** | собственное опорное окно | «изменились ли мы относительно себя» | да |
| **абсолютный** | пороги Венского консенсуса | «где мы относительно стандарта» | нет, но один на всех пациенток |
| **литературный** | механистический каскад Digital Twin | «где мы относительно ожидаемого для ЭТИХ пациенток» | нет |

Собственная база самореферентна: если лаборатория медленно сползает, а опорное окно
переобъявляется, карты не увидят ничего. Венский порог не сползает, но одинаков для
всех. Литературный приор не двигается вместе с нами **и** учитывает пациентку.

## Что система делает и чего не делает

**Делает.** Раз в сутки забирает новые циклы, замораживает для каждого прогнозный
конверт до начала культивирования, на закрытии цикла считает три контура,
риск-скорректированные CUSUM-карты и выносит решение.

**Не делает.** Не поднимает тревог до закрытия цикла — более ранняя тревога
преждевременна и обесценивает систему быстрее, чем пропущенный сигнал. Не объявляет
провалом просадку, укладывающуюся в консенсус.

Последнее — центральное решение проекта. Если лаборатория работает **выше** внешних
опор, её отклонение от собственной истории означает «стало иначе», а не «стало
плохо»:

| относительный | абсолютный | вывод |
|---|---|---|
| просадка | выше benchmark | **тренд**, не провал — смотреть состав пациенток и стимуляцию |
| просадка | ниже competency | разбор лабораторного протокола |
| молчит | ниже competency | давняя разница уровня, плановый разбор, не событие |

## Устройство

```
источник (мастер-таблица OPU → локальный Teable)
   │
   ├─ T0  пункция          → регистрация и ЗАМОРОЗКА конверта (mii, pn2, blasts_early)
   ├─ T+1 оплодотворение   → регистрация конверта blasts_after_fert
   └─ T+6 закрытие         → ЕДИНСТВЕННАЯ точка оценки
         ├─ три контура + RA-CUSUM по эмбрионам
         ├─ QA конверта: факт против P10–P90
         ├─ confounders окна: среда инкубатора, лоты расходников
         └─ вердикт: тренд / разбор протокола / давняя разница
   │
   └─ медленный контур: предсказанная вероятность беременности против факта
```

Порог тревоги не берётся из литературы: цели заданы сверху («не более 2 ложных
`alert` в год по системе»), а `h` вычисляется под них симуляцией in-control процесса
с учётом неопределённости базовой доли, поцикловых блоков и сверхбиномиальной
вариации.

## Установка

```bash
cp config/machine.local.yaml.example config/machine.local.yaml    # пути ЭТОЙ машины
cp config/settings.local.yaml.example config/settings.local.yaml  # токены
python scripts/ews_install.py --clinic <code> --site lab
python scripts/preflight.py
```

Нужен Python 3.10+, локальный Teable и — для модели конверта — интернет на время
установки колёс. Веса модели и обучающая когорта в репозиторий не входят
(233 МБ и данные пациенток соответственно): переносятся отдельно, см.
[`docs/INSTALL_LAB.md`](docs/INSTALL_LAB.md).

## Использование

```bash
python scripts/ews_daily.py     --clinic <code>            # суточная цепочка
python scripts/ews_daily.py     --clinic <code> --weekly   # + обогащение средой
python scripts/ews_run.py       --clinic <code> --replay   # ретроспектива по истории
python scripts/ews_schedule.py  --clinic <code> --install  # расписание Windows
```

## Демо-панель на выгрузке другой лаборатории

Для демонстрации на чужих данных (Excel/CSV только с данными циклов — без логов
инкубатора, лотов и прогонов Digital Twin/TabPFN) — команда `/ews-demo <файл>` в Claude
Code (скилл `ews-demo-dashboard`) или напрямую:

```bash
python scripts/ews_demo.py --input <файл.xlsx|csv> --check-columns   # сопоставление колонок
python scripts/ews_demo.py --input <файл> [--columns override.yaml]  # панель
python scripts/ews_demo_synth.py                                      # синтетический пример
```

Колонки сопоставляются только по точным синонимам из `config/demo/column_aliases.yaml`
(неоднозначное не угадывается), идентификаторы превращаются в `cycle_uid` и удаляются на
входе, имена специалистов заменяются псевдонимами. Панель — автономный HTML
`data/demo/<slug>/EWS_Demo_<slug>.html` в стиле рисунков публикации: KPI против порогов
Венского консенсуса, скользящие доли с ДИ, p-карта Шухарта/Laney, EWMA, CUSUM,
violin по эмбриологам с funnel plot, FR по методу с ECDF, факторы TGBDR, тесты различий
по месяцам и специалистам с выбором метода под сверхдисперсию. Демо всегда
`environment=draft`, `mode=demo` и не поднимает `alert`.

## Новая лаборатория

Метод (математика карт, целевые частоты, правила чекпойнтов) один на всех и лежит в
`config/settings.yaml`. Всё, что различается, — в профиле клиники
`config/clinics/<code>/`: колонки выгрузки, опорное окно, набор карт, импутации.
Запуск на другой лаборатории **не требует правок кода** — только нового профиля;
пошагово в [`docs/RUNBOOK.md`](docs/RUNBOOK.md).

## Приватность

Псевдонимизация выполняется на границе ingest (HMAC `cycle_uid`), дальше по
конвейеру PHI не идёт. В репозиторий не входят: данные пациенток, обучающая когорта,
токены, crosswalk псевдонимов, веса модели, откалиброванные пороги.

## Что измерено и оказалось неверным

Отрицательные результаты записаны наравне с положительными — в
[`docs/METHODOLOGY.md`](docs/METHODOLOGY.md) §5.7–5.9. Коротко:

- **риск-коррекция карт по прогнозу невозможна** на этих данных: проверены модель
  счётов, модель долей (в трёх режимах обучения), литературный приор и CSDI —
  прогноз хорошо предсказывает *счёт* (corr 0.86–0.97) и не предсказывает *долю*
  (0.03–0.16), а нужна именно доля;
- **абсолютный порог по среде инкубатора бессмыслен**: критический эпизод есть у 100%
  циклов (открытие крышки — рутина), различает только объём нагрузки;
- **три расхождения между калибровкой и рантаймом**, найденные сквозным прогоном,
  давали втрое завышенную частоту срабатываний, пока определение события,
  поцикловые блоки и сверхбиномиальная вариация не были согласованы.

## Благодарности и связанные проекты

Механистический каскад литературного контура и итоговые вероятности исхода
происходят из **IVF Digital Twin**; определения KPI, разбор логов инкубатора и работа
с лотами — из **embryo-lab-data**. Соответствующие модули вендорены в
`src/ews/vendor/` как копии (не форк) и синхронизируются
`scripts/ews_sync_vendor.py`.

Пороги и определения — The Vienna consensus (Reprod Biomed Online 2017;35:494–510),
Cairo consensus on the IVF laboratory environment; формулы каскада — Herasight
Table A1, Romanski et al. 2022, Sainte-Rose et al. 2021.
