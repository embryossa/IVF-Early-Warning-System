## 3. Повторить на лабораторной машине

Все команды — из корня проекта.

```bash
git pull

```

### 3.1 `config/machine.local.yaml` (не в git, правится руками)

```yaml
teable:
  # ...существующие поля...
  # База «Two-Line IVF — Digital Twin», таблица Cycles: источник вероятности DT.
  dt_base_id: "<id базы DT в ЛАБОРАТОРНОМ Teable>"
  dt_cycles_table_id: "<id таблицы Cycles этой базы>"

google_sheet:
  export_path: "data/local_private/OPU table.csv"  # если лист скачивается вручную
```

- **ID берутся из лабораторного Teable**, домашние не подойдут. Найти их можно, попросив
  Claude Code перечислить базы и таблицы Teable (`teable_client.connect(cfg).bases()` /
  `.tables(base_id)`).
- **Часовой пояс дат.** База DT пишет `Дата OPU` как местную полночь. Дома метки — 19:00Z,
  отсюда `sync.dt_teable.date_utc_offset_hours: 5`. Если в лабораторной базе час другой —
  поправить этот параметр. Признак ошибки: в `--dry-run` синхронизации «DT найдено 0 из N».
- **Источник OPU.** Если в лаборатории Teable наполняет рабочий ПК, а не CSV, шаг
  синхронизации в `ews_daily` будет «пропущен» (нет файла). Это штатно, остальное пойдёт.

