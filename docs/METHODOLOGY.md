## 1. Единицы наблюдения

| Что | Единица | Почему |
|---|---|---|
| Карты по долям (FR, BlR, TGBDR, OCCR, MIIR, DegR, 3pNR) | **эмбрион / ооцит** | при ~40 циклах в месяц это сотни наблюдений вместо десятков — на уровне циклов мощности нет |
| Карты по конверту (остатки P10–P90) | **цикл** | конверт предсказывает счётчик цикла, а не судьбу отдельного эмбриона |
| Покрытие интервала | **цикл × стадия** | |
| Funnel plot | **группа** (эмбриолог, лот, месяц) | |

Когортная доля — всегда `Σ numerator / Σ denominator`, никогда не среднее долей по строкам.

## 2. Прогнозный конверт и остатки

**Конверт** регистрируется на T0 и замораживается: `TPFN3_<stage>_p10/p25/p50/p75/p90`
для стадий `2pN`, `Bl`, `Good Bl`, `Cryo`, плюс медианы и CI Digital Twin/CSDI
(`med_*`, `p025_*`, `p975_*`, `csdi_ci_*`). Хранится с `model_version` и `run_id`.
Пересчёт конверта после того, как факт стал известен, запрещён (см. правила проекта).

**Стандартизованный остаток** на стадию:

```
z = (факт − P50) / ((P90 − P10) / 2.5631)
```

`2.5631 = 2 × Φ⁻¹(0.9)` — переводит межквантильный размах P10–P90 в оценку σ при
приближении к нормальности.

**Вырожденный интервал (измерено, не предположено).** На счётной величине полоса
шириной ≤ 1 физически не может дать 80% покрытия: дискретность счёта превышает
разрешение интервала. Прогон `scripts/ews_baseline.py` на 5205 наблюдениях четырёх
клиник (2026-08-13) дал: таких наблюдений 12.1%, покрытие в них **0.414** против
**0.812** у остальных; они же раздували `sd(z)` до 25 на стадии «Бласт».
Правило: при `P90 − P10 ≤ 1` стадия помечается `envelope_degenerate` и **в слой
остатков не идёт**. Это ограничение предиктивного интервала на малых счётах, а не
сигнал лаборатории; включить их означало бы обеспечить 12% циклов постоянным ложным
«вне интервала».

**Индикатор попадания**: `in80 = P10 ≤ факт ≤ P90`. Опорная доля — **измеренная**, не
номинальные 0.80: по пригодным наблюдениям 0.812 суммарно и по стадиям 0.759 (2PN),
0.794 (MII), 0.823 (Бласт), 0.878 (Хор.бласт), 0.950 (Витрифицировано). Две последние
стадии заметно перекрывают номинал — их интервалы шире нужного, и чувствительность там
ниже. Сравнение с номиналом 0.80 вместо измеренного давало бы постоянный ложный сигнал
на 2PN и постоянную слепоту на «Хор.бласт».

`blasts_early` и `blasts_after_fert` предсказывают одну и ту же величину `Bl` при разном
объёме знания (до и после того, как известен 2pN). Обе сравниваются с фактом независимо;
расхождение между ними — самостоятельный диагностический признак, а не ошибка.

## 3. Карты

### 3.1 Risk-adjusted CUSUM (основной инструмент)

Steiner SH, Cook RJ, Farewell VT, Treasure T. *Monitoring surgical performance using
risk-adjusted cumulative sum charts.* Biostatistics 2000;1(4):441–452.

Для каждого наблюдения `i` (эмбрион) с модельной вероятностью успеха `p_i` и исходом
`y_i ∈ {0,1}` вклад в статистику при сдвиге шансов в `R` раз:

```
W_i = y_i · log(R) − log(1 − p_i + R · p_i)
C_i = max(0, C_{i−1} + W_i),   сигнал при C_i > h
```

- Детекция **ухудшения** метрики нижнего контроля (FR, ClR, BlR, TGBDR, OCCR, MIIR):
  `R = 0.5` — половинные шансы успеха.
- Для метрик верхнего контроля (DegR, 3pNR) успехом считается нежелательное событие и
  берётся `R = 2.0`.
- `p_i` — риск-скорректированное ожидание из конверта: для стадии с числителем `x` и
  знаменателем `n` берётся `p_i = clip(P50_x / n, 0.01, 0.99)`. Знаменатель — фактический
  (известный на момент оценки), числитель — прогнозный. Если знаменатель 0 — наблюдения нет.
- Состояние `C_i` персистится между прогонами (`ews_charts_state.json`), иначе карта
  теряет память при каждом запуске и перестаёт быть секвенциальной.

**Оценка точки сдвига** после сигнала — последний индекс, где `C_i = 0`. Дополнительно
ретроспективное сравнение «до/после» точным тестом Фишера (справочно, не для решения).

### 3.2 EWMA по остаткам

```
E_t = λ·z_t + (1 − λ)·E_{t−1},   λ = 0.2
пределы: ± L · σ̂ · sqrt( λ / (2 − λ) )
```

`σ̂` — стандартное отклонение `z` в опорном окне (фаза 1), а не теоретическая 1: если
конверт систематически шире или уже реального разброса, теоретическая единица даст неверные
пределы. `L` подбирается симуляцией под тот же ARL, что и CUSUM (§5).

CUSUM и EWMA на одной метрике **сильно скоррелированы** и не считаются независимыми
подтверждениями друг друга (§6).

### 3.3 Funnel plot

Spiegelhalter DJ. *Funnel plots for comparing institutional performance.* Stat Med
2005;24(8):1185–1202. По группам: эмбриолог, лот среды, календарный месяц.

По оси X — объём группы `n`, по оси Y — наблюдаемая доля либо `O/E` (наблюдённое к
риск-скорректированному ожиданию `E = Σ p_i`). Пределы 95% (внутренний) и 99.8% (внешний)
вокруг целевого значения. Внешний предел соответствует уровню `alert` только вместе с
условиями §5–§6.

### 3.4 Покрытие интервала

В скользящем окне последних `W = 40` циклов: доля попаданий `in80` против **измеренного
опорного покрытия своей стадии** (`settings.envelope.baseline_coverage`), односторонний
точный биномиальный тест (проверяется только падение), α = 0.01. Строится по каждой
стадии отдельно **и** агрегированно. Вырожденные интервалы в знаменатель не входят.

Опорное покрытие пересчитывается `scripts/ews_baseline.py` и датируется
(`baseline_coverage_measured_at`). Оно обязано пересчитываться при каждом переобучении
модели конверта: это свойство модели, а не константа.

### 3.5 Медленный контур с риск-коррекцией: исход против ожидания DT

`src/ews/outcome_ra.py`, параметры — `settings.outcome_ra`. Тревог не поднимает и в
эскалации не участвует (неподвижное решение владельца). Отличие от `outcome.py`:
сравниваются не сырые частоты беременности, а факт с ожиданием **для этих пациенток**.

**Почему здесь риск-коррекция возможна, а в §5.8–5.9 — нет.** Там конверт предсказывал
*счёт* стадии и не предсказывал *долю* эмбрионов. Здесь ожидание — итоговая вероятность
DT (L7 BEFE) на перенос, то есть ровно та величина, с которой сравнивается исход
`0/1`. Дискриминация DT внутри одного центра скромная (AUC около 0.55 на Fertimed и
RBMO), поэтому O/E отдельного переноса бессмысленно; смысл появляется на суммах — по
месяцу, лоту, обстановке окна, эмбриологу.

**Калибровка на центр.** DT не калиброван на клинику. Применяется сдвиг одного
интерсепта: `logit p* = logit p_DT + δ`, где `δ` решает `Σ p* = Σ y` на первых
`min_known_calibration` (40) исходах по дате пункции. `δ` **замораживается** в
`state/outcome_calibration.json` и больше не пересчитывается — по той же причине, что
и конверт (§2): ожидание, подогнанное под факт, с которым его сравнивают, ничего не
предупреждает. SE `δ` при n = 40 около 0.33 по логиту. Пока исходов меньше, ожидание —
DT как есть, и панель это печатает. Удаление файла — новая калибровка, её фиксируют
в журнале.

**O/E и funnel.** Для группы `O = Σ y`, `E = Σ p*`, `V = Σ p*(1−p*)`. Пределы для O/E —
`1 ± z·√V / E` при `z` 95% и 99.8% из `charts.funnel` (§3.3): вопрос «совместима ли
группа с ожиданием», а не доверительный интервал её уровня. Группа с менее чем
`min_known_group` (10) исходами показывается, но не оценивается («мало исходов»).
Разрезы: месяц пункции; эмбриолог (псевдоним по числу переносов); нагрузка средой —
критические минуты окна выше верхнего дециля когорты по `ews_window_context.csv`
недельного прохода (окно без разобранных логов — отдельная группа, не «норма»); лот
каждой позиции Airtable в окне `Date OPU..+6`.

**Лоты.** Лот — значение AI (10) GS1 DataMatrix: полный скан несёт ещё GTIN, срок
годности и серийный номер, и две коробки одного лота иначе дали бы два «лота». Затем
нормализация как у формулы `Lot Changed` в Airtable (A-Z0-9) и склейка короткого скана
с полным по вхождению. Окно, в которое попала смена лота, не приписывается ни одному
лоту («смена лота в окне»). Позиции с одним лотом на все переносы не показываются:
сравнивать не с чем.

**VLAD и RA-CUSUM.** VLAD — `Σ (y − p*)` в порядке пункции: недобор (−) или избыток (+)
беременностей против ожидания. RA-CUSUM Бернулли (§3.1) настроен на снижение шансов
беременности вдвое (`R = 0.5`); `h` подбирается симуляцией in-control года
(`target_signals_per_year` = 0.5, объём — переносов с исходом в год по данным, ожидания
разыгрываются из наблюдаемых `p*`). Сигнал CUSUM — наблюдение медленного контура.

**Вердикт «тренд дошёл до результата».** O/E опорного окна ниже внутреннего предела при
не менее `min_known_period` (20) исходах. Иначе контур честно отвечает «не созрел».

**Множественность.** Групп много (месяцы × лоты × позиции), и часть выходов за 95%
ожидаема случайно; панель печатает их число. Это поводы посмотреть, не выводы.

## 4. Разбор «покрытие упало на всех стадиях»

Не является сигналом контура культивирования. Три гипотезы в фиксированном порядке:

1. **Состав пациенток.** Когорта с очень плохим прогнозом даёт системный недобор
   относительно конверта на всех стадиях, и это правда о пациентках. Проверяется первым:
   сдвиг распределения входных признаков (возраст, AMH, AFC, № попытки, `sperm`) в окне
   тревоги против опорного окна — двухвыборочный тест Колмогорова–Смирнова по непрерывным и
   χ² по категориальным, плюс штатный OOD-сигнал Digital Twin (`befe.py`,
   `fit_befe_ood.py`), существующий именно для случая «пациентка вне области обучения».
2. **Дрейф модели.** Признаки: сдвига признаков нет, покрытие ниже номинала, растёт
   `mae_p50`, велика давность последней калибровки. Вывод — аудит модели, не разбор
   лаборатории.
3. **Общелабораторный фактор.** Остаётся, только когда первые две отвергнуты.

До завершения разбора карта покрытия **блокирует эскалацию до `alert`** (тревоги остаются
`watch`), но сами тревоги не гасит и из журнала не удаляет.

## 5. Пороги, ARL и уровни тревог (принятое решение)

### 5.1 Целевые частоты

Решение принимается сверху вниз, от цены ошибки, а не от литературных значений `h`.

| Уровень | Что делает | Цена ложного | Целевая частота (система целиком, in-control) |
|---|---|---|---|
| `watch` | строка на панели, никого не будит | минуты внимания | **≤ 2 в месяц** |
| `alert` | инициирует разбор: инкубатор, среда, лот, воздух, оператор | часы работы, возможная остановка лота, подрыв доверия к системе | **≤ 2 в год** (≈ одна на 6 месяцев) |

Обоснование верхней строки: `watch` не имеет цены, кроме внимания, и должен ловить рано —
два в месяц на панели, где их видит один человек, приемлемо. Обоснование нижней:
разбор — это остановка нормальной работы лаборатории, а ложный разбор дороже пропущенного
события ровно потому, что после второго-третьего пустого срабатывания систему перестают
читать вообще. Шесть месяцев выбраны как период наблюдения из исходной статьи (Bormann
2021) — он же примерно равен сроку, за который лаборатория успевает пройти полный цикл
смены партий сред.

### 5.2 Как это превращается в `h`

`h` **не задаётся вручную**. `scripts/ews_backfit.py` решает обратную задачу:

1. Оценивает in-control параметры на исторической выгрузке (распределение `z`, базовые
   доли, фактический объём эмбрионов и циклов в месяц).
2. Bootstrap-симуляцией in-control процесса подбирает по каждой карте:
   - `h_watch` такое, что частота ложных сигналов ≤ `24 / m` в год,
   - `h_alert` такое, что частота ложных сигналов ≤ `2 / m` в год,
   где `m` — число активных карт (не константа: карта без данных не считается).
3. Записывает найденные `h`, дату калибровки, объём обучающего окна и измеренные частоты
   в `config/settings.yaml` и в `calibration_manifest.json`.

Пока калибровка не выполнена (`thresholds.calibrated: false`), система **физически не может
выдать `alert`** — только `watch`. Гейт снимается записью бэкфита, не руками. Это защита от
самого дорогого сценария: остановленный лот среды по неоткалиброванному порогу.

### 5.3 Два маршрута к `alert`

```
alert  ⇐  C_i > h_alert                                    (порог сам по себе)
alert  ⇐  C_i > h_watch  И  сильное независимое подтверждение   (быстрый маршрут)
watch  ⇐  C_i > h_watch
```

Второй маршрут даёт настоящему событию сработать раньше, не раздувая частоту ложных: смена
лота и эпизод инкубатора — физически независимые от биологии источники, их совпадение с
биологическим сигналом маловероятно случайно. Обе ветви участвуют в симуляции §5.2 — целевая
частота относится к их **сумме**, а не к первой ветви отдельно.

### 5.4 Множественность

Целевые частоты — **совместные по всем картам**, а не по каждой отдельно. Добавление новой
карты автоматически ужесточает `h` всех остальных при следующем бэкфите (`m` растёт). Это
сознательно: иначе расширение панели тихо повышало бы поток ложных тревог.

### 5.5 Реальный объём лаборатории и что из него следует

Измерено на мастер-таблице (91 цикл, декабрь 2025 — август 2026): **≈10 циклов и ≈70
эмбрионов (2PN) в месяц**, то есть ≈120 циклов и ≈840 эмбрионов в год. Это вчетверо
меньше, чем закладывалось при первом наброске методологии, и меняет арифметику порогов.

При совместной цели «2 ложных `alert` в год» и `m` активных картах требуемый in-control
ARL₀ каждой карты ≈ `840 · m / 2` эмбрионов:

| `m` | ARL₀ на карту | в годах работы |
|---|---|---|
| 7 карт (все метрики) | ≈ 2940 эмбрионов | ≈ 3.5 года |
| 5 карт | ≈ 2100 | ≈ 2.5 года |
| **3 карты (по одной на контур)** | **≈ 1260** | **≈ 1.5 года** |

Чем выше требуемый ARL₀, тем выше `h` и тем позже срабатывание на настоящем сдвиге. При
таком объёме честный вывод один: **правильный рычаг — сокращать число карт, а не ослаблять
цель по ложным тревогам.** Меньше карт дают одновременно и меньший поток ложных, и более
низкий порог, то есть более раннюю детекцию — это редкий случай, когда обе стороны размена
выигрывают.

Конфигурация карт: **три CUSUM-карты, по одной на контур** — FR (эмбриолог),
BlR (культивирование), **MIIR** (врач). Остальные метрики считаются и показываются на
панели как абсолютные Венские показатели с CI, но собственной секвенциальной карты не
получают. TGBDR, DegR, 3pNR и ClR при этом остаются полноценными источниками
**умеренного подтверждения** (§6) — для этого карта не нужна.

**Почему врачебная карта — MIIR, а не OCCR.** Знаменатель OCCR — число фолликулов,
субъективный счёт врача на пункции. Он дрейфует вместе с практикой счёта и имитирует сдвиг
процесса. Подтверждено на своих данных: между периодами до и после мая 2026 OCCR упал на
7.6 пп (p = 0.001), при этом фолликулов на цикл стало на 12% больше, а ОКК на цикл не
изменилось вовсе (13.3 → 13.4, p = 0.84). Изменился знаменатель, а не результат. Карта на
такой метрике ловила бы изменения в том, как считают, а не в том, как работают.
Знаменатель MIIR — ОКК, объективный счёт ооцитов в чашке; той же уязвимости у него нет.
Общее правило: **метрика с субъективным знаменателем не получает секвенциальной карты**,
даже если её объём это позволяет.

Симуляция — параметрический бутстрап с розыгрышем истинной доли из Beta(x+½, n−x+½), карта

| FR | 0.819 | 1337 | 0.090 | 1.22 | 8.27 | 7.44 | 0.64 | 1.2 мес |
| BlR | 0.590 | 1095 | 0.230 | 1.78 | 7.77 | 10.83 | 0.69 | 1.7 мес |
| MIIR | 0.771 | 1734 | 0.108 | 1.73 | 7.98 | 10.01 | 0.64 | 1.1 мес |

По системе целиком: **24.0 ложных `watch` в год** (цель ≤ 24) и **1.97 ложных `alert` в
год** (цель ≤ 2).

**Проверено сквозным прогоном, а не только симуляцией.** Replay по всей истории даёт
внутри опорного окна **21 эпизод `watch` в год** против калиброванных 24 — калибровка и
рантайм измеряют одно и то же событие. Вне опорного окна (до мая) частота выше, 26/год,
и это не ложные тревоги: карта честно говорит, что тогда лаборатория отличалась от того,
что сейчас объявлено нормой. Сравнивать измеренную частоту с целевой имеет смысл только
внутри опорного окна.

**Целевая функция — частота сигналов, а не средняя длина серии.** Как только истинная доля
разыгрывается, у части прогонов (там, где реальность оказалась лучше базовой оценки) время
до сигнала фактически бесконечно, и среднее упирается в горизонт симуляции вместо того,
чтобы отражать реальность. По неравенству Йенсена `E[1/ARL] ≠ 1/E[ARL]`, а цель поставлена
именно как `E[1/ARL]` — «сколько ложных тревог в год увидит лаборатория». Первая реализация
решала задачу через ARL и давала `h_alert ≈ 3.9`; корректная постановка даёт `≈ 4.7`, то
есть прежние пороги были заметно мягче заявленной цели.

**На какой сдвиг карты настроены.** Медиана задержки до `alert` при разной силе сдвига:

| сдвиг шансов | FR | BlR | MIIR |
|---|---|---|---|
| ×0.5 (половина) | 0.7 мес | 0.6 мес | 0.5 мес |
| ×0.6 | 1.0 | 0.9 | 0.8 |
| ×0.7 | 2.0 | 1.5 | 1.4 |
| ×0.8 | 4.1 | 3.4 | 3.0 |

Резкое ухудшение ловится за 2–3 недели. Медленное сползание (шансы ×0.8 — например, BlR
0.590 → 0.535) обнаруживается за 3–4 месяца, и это честный предел метода на объёме ~70–140
наблюдений в месяц, а не дефект настройки: на таком объёме сдвиг в 5 пп статистически
неотличим от шума быстрее. Ускорить можно только увеличением объёма или ослаблением цели по
ложным тревогам — оба рычага в руках владельца.

### 5.7 Три расхождения между калибровкой и рантаймом (найдены прогоном фазы 2)

Первый сквозной прогон по истории дал **64 эпизода `watch` в год внутри опорного окна**
против калиброванных 24. Расхождение оказалось не одной ошибкой, а тремя, и каждая
исправлена в сторону совпадения модели с реальностью, а не наоборот.

**1. Разное определение события.** Симуляция считала пересечения с перезапуском
статистики, а рантайм перезапускает её только на `alert`; `watch` — это эпизод
(пересечение снизу вверх), и он не сбрасывает счётчик. Пока событие определялось
по-разному, измеренная частота не имела отношения к тому, что видит человек.
Исправлено единой реализацией `charts.CusumRunner`, которую используют **и** бэкфит,
**и** боевой прогон: разойтись они больше не могут.

**2. Порядок эмбрионов внутри цикла.** Рантайм разворачивал цикл в
последовательность «сначала все успехи, потом все неудачи». Любой фиксированный
порядок создаёт артефакт, а этот — наихудший: максимальная экскурсия в конце каждого
цикла. Порядок эмбрионов внутри цикла не наблюдаем в принципе — их исходы становятся
известны одновременно, на закрытии. Карта теперь делает **одно обновление на цикл**
суммарным вкладом (`step_block`). Вклад тот же — мощность по-прежнему даёт число
эмбрионов, — но траектория лишена внутрицикловых пиков, которых никто не наблюдает.

**3. Сверхбиномиальная вариация между циклами.** Главная и наименее очевидная.
Симуляция разыгрывала все циклы года при одной доле `p`, а доля успеха реально
различается от пациентки к пациентке сверх биномиального шума. Измерено по опорному
окну (статистика Пирсона X²/df):

| метрика | X²/df | ρ (внутриклассовая корреляция) |
|---|---|---|
| FR | 1.84 | 0.090 |
| MIIR | 2.33 | 0.108 |
| BlR | **2.76** | **0.230** |

Разброс вдвое-втрое выше биномиального. Карта видела вариацию, которой не было в
модели порога, и пересекала его существенно чаще предсказанного. Калибровка теперь
разыгрывает долю каждого цикла из бета-биномиальной модели с измеренным ρ.

**Что из этого следует для конструкции.** Сверхбиномиальная вариация — это ровно та
разнородность пациенток, которую должна поглощать риск-коррекция по конверту
(`p_i = P50 / знаменатель` вместо общей `p₀`). Пока конверт не зарегистрирован для
всех циклов, карты работают на базовой доле, вариация остаётся неучтённой, и цена
этого — более высокие пороги и более поздняя детекция. После подключения конверта ρ
надо **измерить заново**: он должен упасть, и тогда пороги можно опустить. Это не
теоретическое улучшение, а измеримое: `overdispersion.rho` в
`incontrol_parameters.json` — прямой индикатор того, сколько ещё можно выиграть.

### 5.8 Риск-коррекция по конверту: отрицательный результат

Ожидание было прямым: заменить общую базовую долю `p₀` на индивидуальную
`p_i = P50 / знаменатель`, поглотить разнородность пациенток, снизить ρ и опустить
пороги. Конверты зарегистрированы (91 цикл × 2 чекпойнта), измерение проведено — и
**дало обратное**:

| метрика | X²/df с `p₀` | X²/df с конвертом |
|---|---|---|
| MIIR | 2.33 | **11.92** |
| FR | 1.83 | 3.80 |
| BlR | 2.76 | **14.48** |

**Причина не в качестве прогноза.** P50 согласован с фактом: корреляция 0.91 (mii),
0.97 (pn2), 0.86 (blasts_after_fert), смещение меньше одного эмбриона. Модель
предсказывает хорошо.

**Причина в подстановке точечной оценки как известной вероятности.** Отношение
`P50/n` берётся так, будто риск цикла известен точно. У `mii` внешняя модель ограничена
сверху числом ОКК, и **49% циклов дают `p_i ≥ 0.95`**. Там биномиальная дисперсия
`n·p·(1−p)` вырождается: при `n=7, p=0.99` она равна 0.069, и один промах (наблюдено 4
из 7) даёт вклад в статистику **124** при медианном 5. У `blasts_after_fert` то же на
обоих концах: `p_i = 0.02` при наблюдённых 3 из 3 даёт вклад 124.

Иначе говоря: карта наказывает лабораторию за уверенность модели. Ширина P10–P90
существует ровно для того, чтобы эту уверенность измерить, и выбрасывать её,
оставляя одну медиану, — методическая ошибка, а не упрощение.

**Что сделано.** Риск-коррекция закрыта гейтом `envelope.risk_adjustment_enabled:
false`. Система работает на базовой доле — в том состоянии, для которого пороги
откалиброваны и проверены сквозным прогоном. Конверты продолжают регистрироваться и
замораживаться: они уже пригодны как независимый QA-слой (факт против P10–P90) и
понадобятся, как только `p_i` научится учитывать ширину интервала.

### 5.9 Почему риск-коррекция невозможна этим конвертом (окончательно)

Бета-биномиальное правдоподобие реализовано (`charts.beta_binomial_weight`,
`concentration_from_interval`): риск цикла считается `p ~ Beta` со средним `P50/n` и
концентрацией из ширины `P10–P90`, вес CUSUM — маргинальное отношение
правдоподобий. Это убрало взрыв весов: максимальный |W| упал с 7.4 до 2.1–4.2.

Но согласованность дисперсии всё равно осталась хуже простой базовой доли:

| метрика | базовая доля `p₀` | точечная `P50/n` | бета-биномиальная |
|---|---|---|---|
| MIIR | **2.33** | 11.92 | 4.56 |
| FR | **1.85** | 3.80 | 2.56 |
| BlR | **2.76** | 14.48 | 7.80 |

Причина найдена и она принципиальная. Корреляция прогноза с фактом высока по
**счёту** и отсутствует по **доле**:

| стадия | corr(счёт) | corr(доля) |
|---|---|---|
| mii | 0.91 | **0.13** |
| pn2 | 0.97 | **−0.08** |
| blasts_after_fert | 0.86 | **0.16** |

Высокая корреляция счёта — артефакт знаменателя: и факт, и прогноз растут вместе с
числом ооцитов, поэтому «модель хорошо предсказывает» здесь означает лишь «модель
знает, сколько было ооцитов». Риск-коррекции нужна **доля**: какая часть именно у
этой пациентки дойдёт до следующей стадии. Этой информации в конверте нет.

**Вывод.** Дело не в реализации `p_i` и не в бета-биномиале. Индивидуальный риск,
которого нет в прогнозе, нельзя извлечь никаким преобразованием прогноза.
Следствия, важные для проекта:

1. Гейт `risk_adjustment_enabled` остаётся закрытым, и теперь по доказанной, а не
   предполагаемой причине. Карты работают на базовой доле — том состоянии, для
   которого пороги откалиброваны и проверены.
2. Измеренная сверхбиномиальная вариация (ρ = 0.09–0.23) — **не** необъяснённый
   case-mix, который «когда-нибудь снимет риск-коррекция». Это либо подлинная
   биологическая вариация, либо разнородность, которой нет в признаках модели.
   Рассчитывать на снижение порогов за счёт риск-коррекции больше нельзя.
3. Задача «научить модель предсказывать долю, а не счёт» — модельная, а не задача
   EWS. До её решения конверт остаётся тем, чем он полезен уже сейчас: независимым
   QA-слоем «факт против P10–P90».

Код бета-биномиала сохранён и покрыт тестами: как только появится модель,
предсказывающая долю, машинерия готова и гейт открывается одной строкой конфига.

**Оставшееся упрощение калибровки.** Симуляция ведётся при одной базовой доле на
метрику. Пока риск-коррекция выключена, это не упрощение, а точное соответствие
рантайму.

## 6. Подтверждение: ранг источников

| Источник подтверждения | Ранг | Годится для «быстрого маршрута» §5.3 |
|---|---|---|
| Эпизод MIRI в окне `Date OPU..+6` | сильный (физически независим) | да |
| Смена лота среды/расходника в окне (Airtable) | сильный (физически независим) | да |
| Другая метрика того же контура (BlR + TGBDR) | умеренный (корреляция через общую биологию) | нет |
| Та же метрика на другой карте (CUSUM + EWMA) | **слабый — подтверждением не является** | нет |
| Флаги OZEMA цикла | умеренный | нет |

### 6.1 Подтверждение обязано быть ОТНОСИТЕЛЬНЫМ (найдено измерением)

Первая реализация считала подтверждением сам факт: есть критический эпизод MIRI в
окне или есть смена лота. Прогон по 49 циклам, покрытым выгрузками логов, показал,
что так оно не работает:

| источник | за 49 циклов | на цикл |
|---|---|---|
| эпизоды инкубатора всего | 3113 | ~64 |
| из них `critical` | 1084 | ~22 |
| `o2_excursion` / `co2_excursion` / `lid_open` | 1418 / 961 / 612 | — |
| смены лота | 66 | ~1.3 |

**Сильное подтверждение срабатывало у 49 циклов из 49.** Источник, присутствующий
всегда, не подтверждает ничего: быстрый маршрут `watch → alert` повышал бы уровень
каждой тревоге, то есть делал ровно обратное задуманному.

Причина не в ошибке разбора. За шесть суток на шести камерах открытие крышки — это
рутинная работа эмбриолога, а не происшествие; экскурсии O₂/CO₂ после каждого
открытия — физика, а не сбой. Классификация `severity` в `embryo-lab-data`
рассчитана на форензику ОТОБРАННОГО цикла, который читает человек, и как
автоматический бинарный флаг непригодна по назначению.

**Правило.** Подтверждение считается по тому же принципу, что и всё остальное в
системе: сравнением с базой, а не с абсолютным порогом. Окно цикла подтверждает
тревогу, только если его нагрузка средой **необычна на фоне других циклов** —
например, критические минуты в верхнем дециле распределения. Абсолютный порог
«есть критический эпизод» запрещён: он всегда истинен.

Та же логика распространяется на смену лота: сама по себе она рутина, значимо
совпадение необычно большого числа замен либо замена ровно в окне просадки.

Последняя строка таблицы выше — то, ради чего она написана. Согласие CUSUM и EWMA на одной
метрике выглядит как два независимых свидетельства и им не является: обе карты питаются
одним и тем же рядом. Подавать их как двойное подтверждение запрещено — это ровно та ошибка,
которую `interpretation-critic` в `embryo-lab-data` поймал на реальном отчёте.

## 8. Чего методология не делает

- Не оценивает конкретного специалиста. Просадка контура эмбриолога — повод разобрать
  процесс, а не человека; формулировка в артефактах — «повод для дополнительного разбора».
- Не использует дискриминативные метрики моделей (Brier, ROC-AUC, Acc@0.5) — на когортах
  этого масштаба они статистически неотличимы от шума.
- Не считает биномиальный CI при `numerator > denominator` (`ClR > 100%`, `MII > OCC`):
  интервал математически не определён. Сама доля остаётся и интерпретируется по причинам,
  описанным в правилах проекта.
- Не заявляет причинности. Совпадение эпизода среды и просадки — кандидат-объяснение;
  проверка связи — отдельная задача фазы 3 на накопленных данных.
